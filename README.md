# WolBot — включение домашнего ПК по Wake-on-LAN из Telegram

Бот крутится на машине, которая всегда включена и стоит в той же локальной сети,
что и целевой компьютер (сервер Proxmox / Debian / Ubuntu). По команде шлёт
magic packet и ждёт, пока ПК реально поднимется.

## Команды

| Команда   | Что делает                                                   |
|-----------|--------------------------------------------------------------|
| `/wake`   | Шлёт magic packet и опрашивает хост, пока тот не отзовётся    |
| `/status` | Проверяет, включён ли ПК (TCP-порты + ping)                   |
| `/id`     | Показывает ваш Telegram ID — нужен для `ALLOWED_USERS`        |
| `/start`  | Меню с кнопками «Включить» / «Статус»                         |

Доступ — по белому списку Telegram ID. Всем остальным бот отвечает отказом
и пишет об этом в журнал. `/id` намеренно отвечает всем: иначе не узнать свой ID.

## Установка

Одной командой на машине, которая всегда включена и стоит в одной сети с целевым ПК:

```bash
curl -fsSL https://raw.githubusercontent.com/youenmy/WOL_Bot/main/install.sh | sudo bash
```

Затем настроить — токен, MAC и адрес компьютера, список разрешённых ID:

```bash
sudo wolbot
```

Из клона репозитория то же самое делает `sudo ./install.sh` — скрипт понимает оба
режима: если рядом с ним нет исходников, он их скачивает сам.

`install.sh` создаёт системного пользователя `wolbot`, venv в `/opt/wolbot`,
конфиг `/etc/wolbot.env` (права 640, читает только группа `wolbot`), юнит systemd
и команду `wolbot`. Повторный запуск безопасен: существующий конфиг не трогается.

## Управление: команда `wolbot`

Скрипт лежит в `/opt/wolbot/wolbot-cli.sh`, в `/usr/local/bin/wolbot` — симлинк
на него. Требует root. Без аргументов открывает меню:

```
  WolBot — Wake-on-LAN из Telegram
  ────────────────────────────────────
  служба: ● сбой     цель: 10.10.10.10

  ▸ 1) Состояние (служба + компьютер)
    2) Разбудить компьютер
    3) Журнал — последние 50 строк
    4) Журнал — в реальном времени
    5) Запустить / перезапустить службу
    6) Остановить службу
    a) Автозапуск вкл/выкл
    r) Запросы доступа
    7) Задать токен бота
    8) Задать список разрешённых ID
    9) Показать настройки
    e) Редактировать настройки
    u) Обновить код из /opt/wolbot/src
    0) Выход
```

Управление — мышью или с клавиатуры, как удобнее:

- **клик** по строке пункта, **колесо** прокручивает выделение;
- **↑ ↓** и **Enter**;
- клавиша пункта (`1`, `a`, `e`, `u`, `0`), `q` — выход.

Пункты помечены буквами, а не числами 10–12, чтобы каждая клавиша срабатывала
сразу, без ожидания второй цифры.

Мышь работает в Windows Terminal, PuTTY и в Shell веб-интерфейса Proxmox — везде,
где терминал поддерживает mouse reporting. Захват мыши мешает выделять текст
мышкой, поэтому есть клавиша **`m`**: выключает и включает его обратно.

Меню открывается на альтернативном экране, поэтому после выхода содержимое
терминала и прокрутка остаются как были. Вывод действий печатается на обычном
экране — журнал можно листать.

## Выдача доступа: «Запросы доступа»

Переписывать Telegram ID руками не нужно. Когда незнакомый человек пишет боту,
тот отвечает отказом, говорит «заявка отправлена владельцу» и дописывает запись
в `/var/lib/wolbot/requests.json` — id, имя, username, сколько раз обращался и когда.

В меню пункт **`r) Запросы доступа`** показывает эти заявки списком:

```
  Запросы доступа
  ────────────────────────────────────

  ▸ 555000111    Тест Тестов · @testuser · обращений: 3 · 19.08 02:50

  сейчас доступ у: 123456789

  клик или Enter — выдать доступ · d — удалить заявку
  r — обновить · 0 — назад
```

Клик по строке дописывает ID в `ALLOWED_USERS`, убирает заявку и перезапускает
службу. `d` — отклонить и забыть. Если заявок нет, счётчик в шапке главного
меню не показывается; когда есть — там появляется «заявок: N».

Так же и без меню:

```bash
wolbot requests           # посмотреть заявки
wolbot approve 123456789  # выдать доступ
```

Каталог `/var/lib/wolbot` создаёт systemd через `StateDirectory=wolbot` — это
единственное место, куда служба может писать при `ProtectSystem=strict`.

## Все команды

| Команда | Что делает |
|---|---|
| `wolbot status` | состояние службы, наличие токена, онлайн ли ПК |
| `wolbot wake` | разбудить и дождаться отклика |
| `wolbot sleep` | усыпить и дождаться, пока отключится |
| `wolbot requests` | заявки на доступ |
| `wolbot approve ID` | выдать доступ |
| `wolbot logs [-f]` | журнал, `-f` — в реальном времени |
| `wolbot start\|stop\|restart` | управление службой |
| `wolbot config` | показать настройки, токен замаскирован |
| `wolbot edit` | открыть конфиг в `$EDITOR` и перезапустить службу |
| `wolbot update` | забрать код из `/opt/wolbot/src` и перезапустить |

Токен вводится скрыто и проверяется на формат; список ID — только цифры через
запятую. Конфиг переписывается построчно, права `640 root:wolbot` сохраняются.

## Куда что ставится

| Что | Где |
|---|---|
| Код | `/opt/wolbot`, venv `/opt/wolbot/venv` |
| Исходники | `/opt/wolbot/src` (из них работает `wolbot update`) |
| Меню | `/opt/wolbot/wolbot-cli.sh`, симлинк `/usr/local/bin/wolbot` |
| Конфиг | `/etc/wolbot.env` (root:wolbot, 640) |
| Состояние | `/var/lib/wolbot/requests.json` — заявки на доступ |
| Ключ для сна | `/etc/wolbot/id_sleep` (root:wolbot, 640) |
| Служба | `wolbot.service`, автозапуск включён |

Обновление на месте — пункт меню «Обновить код» или `wolbot update`: он забирает
исходники из `/opt/wolbot/src`, проверяет синтаксис и только потом перезапускает
службу. Если код сломан, работающий бот не трогается.

## Настройка

Все параметры — в `/etc/wolbot.env`, образец в [.env.example](.env.example).

Обязательные: `BOT_TOKEN`, `ALLOWED_USERS`, `PC_MAC`, `PC_HOST`.

**`BROADCAST_IP`** стоит указать явно (`10.10.10.255` для сети `10.10.10.0/24`).
`255.255.255.255` уходит только в один интерфейс — тот, что выбрало ядро, и на
машине с мостами Proxmox это может быть не тот интерфейс.

**`CHECK_PORTS`** — по каким портам считать ПК живым. Windows по умолчанию не
отвечает на ping в профиле «Общедоступная сеть», поэтому одного ICMP мало.
3389 (RDP) и 445 (SMB) работают, только если соответствующие службы включены;
если ни то ни другое — поставьте любой заведомо открытый порт.

## Сон: как настроить

Разбудить компьютер можно «снаружи» — сетевая карта слушает сеть сама.
Усыпить — нельзя: нужен кто-то на стороне Windows, кто выполнит команду.
Поэтому бот просто запускает то, что записано в `SLEEP_COMMAND`, и ждёт,
пока хост перестанет отвечать. Пустое значение — кнопка «Усыпить» честно
скажет, что сон не настроен.

Рабочий способ без стороннего софта — OpenSSH Server, он встроен в Windows.

**1.** На целевом ПК, в PowerShell **от администратора**:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service sshd -StartupType Automatic
Start-Service sshd
```

**2.** Разрешить вход по ключу с сервера — там же, подставив свой публичный ключ:

```powershell
$key = 'ssh-ed25519 AAAA... wolbot-sleep@pve'
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
Add-Content "$env:USERPROFILE\.ssh\authorized_keys" $key
```

Ключ кладётся обычному пользователю, не администратору: усыпить машину может
любая учётка, а `administrators_authorized_keys` дал бы боту куда больше прав,
чем ему нужно.

**3.** На сервере прописать команду в `/etc/wolbot.env`:

```
SLEEP_COMMAND=ssh -i /etc/wolbot/id_sleep -o StrictHostKeyChecking=accept-new -o ConnectTimeout=10 ИМЯ@10.10.10.10 "powershell -NoProfile -Command \"Add-Type -AssemblyName System.Windows.Forms; [System.Windows.Forms.Application]::SetSuspendState('Suspend',$false,$false)\""
```

Ключ лежит в `/etc/wolbot/id_sleep` (640 root:wolbot), пара к нему сгенерирована
при настройке.

Почему именно `SetSuspendState('Suspend', ...)`, а не привычный
`rundll32 powrprof.dll,SetSuspendState 0,1,0`: последний уходит в гибернацию,
если она включена. Явный `Suspend` всегда даёт сон (S3). Заодно проверьте,
что S3 вообще доступен:

```powershell
powercfg /a
```

Сон и WOL связаны: чтобы разбудить машину из S3, в свойствах сетевой карты
должно быть разрешено «выводить компьютер из ждущего режима».

## Чтобы WOL вообще работал

На стороне целевого ПК:

1. В BIOS/UEFI включить *Wake on LAN* / *Power On by PCI-E* / *ErP = Disabled*.
   Если ErP/EuP включён, плата обесточивает сетевую карту в выключённом состоянии.
2. Windows → Диспетчер устройств → сетевая карта → Управление электропитанием:
   «Разрешить этому устройству выводить компьютер из ждущего режима» и в
   «Дополнительно» → *Wake on Magic Packet = Enabled*.
3. Отключить быстрый запуск: Панель управления → Электропитание → Действия
   кнопок питания → «Включить быстрый запуск» снять. Иначе Windows уходит в
   гибридное выключение, и карта часто не слушает сеть.
4. Wi-Fi обычно не годится — нужен провод.

На стороне сети: бот должен быть в том же L2-сегменте (broadcast не маршрутизируется).
Если бот в LXC/VM на Proxmox — контейнер должен быть в бридже `vmbr0` с той же
подсетью, а не за NAT.

## Проверка вручную

```bash
sudo apt install wakeonlan && wakeonlan -i 10.10.10.255 AA:BB:CC:DD:EE:FF
```

Если так ПК не включается — проблема не в боте, а в BIOS/драйвере/сети.
